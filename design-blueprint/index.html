01 · Executive Audit

What the research found, dimension by dimension.

Scored against four UX dimensions audited directly from the live product and its source: src/index.css, layouts, dashboard, and billing flows. Honest scores, specific fixes.

Hierarchy & Information Architecture

68/100

"Functional but visually flat"

Observed

  • KPI cards lack visual rhythm — titles and values compete; no sparklines or trend context
  • Scanning multiple properties creates fatigue; rows lack status grouping
  • No "start here" moment — the dashboard greets but doesn't direct

Everyday Micro-task UX

74/100

"Great core logic, friction in daily flows"

Observed

  • Electricity entry takes 3+ taps per room with manual mental math
  • Sharing receipts on WhatsApp = download, switch apps, attach — every single time
  • Payment verification lacks batch-approval gestures

Motion & State Transitions

52/100

"The weakest link — feels static where it matters most"

Observed

  • Recording a payment closes a modal with zero tactile confirmation
  • Status badges are static pills; tab changes shift abruptly
  • The money moment — "₹67,300 received" — deserves celebration, gets silence

Design-System Discipline

65/100

"Strong palette instinct; token drift crept in"

Observed

  • Cold slate remnants fight the warm palette — chart theme uses indigo #4f46e5, dark inputs use slate #1e293b vs. warm card #16130f
  • Inconsistent radii across dialogs, cards, inputs
  • Charts don't inherit the brand; gradients are default Recharts

✓ Keep — this is your moat

  • The "Warm Ledger" palette (deep teal + marigold on paper-cream) is genuinely distinctive — no generic SaaS look
  • Fraunces + Inter with tabular numerals — the right typographic instinct; ₹ columns align
  • Real dark mode, reduced-motion support, installable PWA, offline shell
  • Financial engine integrity: idempotent billing, carry-forward balances, meter-reset protection — the hard part is done

! Fix — where the modern feel leaks away

  • Token drift: slate grays vs. warm cream in inputs, scrollbars, charts, secondary buttons
  • No money-forward dashboard: data is shown, not staged — no collection ring, no "needs attention" triage
  • Silent money moments: payments, receipts and full-collection milestones pass without feedback
  • Visibility ceiling: HashRouter URLs, no per-route titles, no OG image, no landing page — the product is near-invisible to search and social

Radius scale

Concentric discipline: outer cards 16–20px, inner items 12px, buttons & inputs 10–12px, pills 999px. Inner radius = outer − padding.

Elevation (3 levels, warm)

Rest → hover → overlay. Shadows tinted with warm umber (28,26,22), never neutral black — this is what makes surfaces feel like paper instead of glass.

Motion tokens

Hover me · spring 300/25 250ms · cubic-bezier(.16,1,.3,1) Count-up · easeOutExpo 1.2s

One spring curve for entrances, 150ms ease for exits, stagger 30–40ms per item. Everything honors prefers-reduced-motion.

05 · Motion & Micro-interactions

Money deserves ceremony.

The difference between "works" and "feels premium" lives in the 300 milliseconds after a user acts. Six patterns, all demonstrated live.

₹0

Count-up totals

Every money figure springs from 0 with easeOutExpo on mount and on change (hover to replay). Landlords feel the number land — the single most requested "delight" in finance UIs.

← Swipe Amit's cash payment✓ Approve · ✎ Edit

Swipe-to-approve

Unconfirmed UPI/cash payments approve with a swipe on mobile — batch-verifying ten payments takes seconds, not taps. Desktop keeps row-hover action rails.

Ripple + toast + undo

Recording a payment: soft ripple, sheet slides away, a toast confirms "₹9,500 recorded — Undo". Optimistic UI updates the ledger instantly; Supabase syncs behind it.

Staggered reveal 01 Staggered reveal 02 Staggered reveal 03

Staggered grids

You already ship stagger-grid — extend it to every list: tenants, bills, receipts cascade in at 30–40ms intervals instead of popping as one block.

Sheets, not modals

Replace center-screen modals with bottom sheets on mobile (they already match your thumb zone) and right-side slide-overs on desktop. Context stays visible; dismissal is a swipe, not a hunt for ✕.

🎉 100% collected

Milestone moments

When a month hits 100% collection, a restrained teal-and-gold confetti burst + "Krishna Residency fully collected" card. Once a month, ten seconds — that's the memory users talk about.

Bottom sheet — proposed pattern

On mobile, every form (payment, meter reading, tenant) opens here. The page context stays visible above; closing is a downward swipe. On desktop the same component docks as a right slide-over.

06 · Page-by-Page Blueprint

Every surface, one pass.

Highest-leverage changes per page — all compatible with your existing Supabase schema and services layer.

◆ Login & Auth

First impression, highest bounce risk, already owns a beautiful gradient.

  • Split-screen brand moment: left = form on paper-cream; right = a live "ledger panel" with softly animated stats (properties managed, receipts issued) behind the teal→gold gradient — the product demoing itself
  • Mode switching (sign in / sign up / forgot) with animated height morph, not page jump; inline validation, generous 56px targets for elderly users — keep them
  • Add UPI + WhatsApp trust chips and a one-line "Works offline · Install as app" reassurance

⌂ Properties & Rooms

Your cover-photo instinct is right — push it further into architecture-forward cards.

  • Unit-grid cards: each room as a tile color-coded by state (teal = occupied, amber = notice, coral = overdue, dashed = vacant with "idle ₹/mo" loss figure)
  • Hover popover per room: tenant, move-in date, deposit balance, active meter ID
  • Bulk WhatsApp rent reminder broadcaster with a template builder — merges your send-bill Edge Function

◉ Tenants & Detail

A tenant is a relationship with history — render it as a timeline, not rows.

  • Avatar rows (already built) + status rail: paid-through date, balance, next revision — scannable in one glance
  • Tenant detail = banking-grade ledger timeline with mode icons, receipt chips, and rent-revision markers on a vertical line
  • Move-out flow as a guided 3-step sheet (final reading → settlement preview → confirm) with the deposit math shown before commitment

⚡ Billing & Electricity

Month-end is your product's Oscars — make the batch wizard the hero.

  • Batch billing wizard: one screen, all rooms, pre-filled readings, keyboard-first; a live "₹ total to bill" footer; idempotent "Generate" (your unique constraint) surfaced as safe progress
  • Quick Meter Dial (see Lab): slider or big-digit input, live units × rate, meter-reset guard inline
  • Tenant-facing bill breakdown: rent + electricity + other, each on its own line with the units math shown — kills "why is my bill ₹X" WhatsApp threads

▣ Tenant Portal

Tenants judge the whole product by this screen — make it a passbook they love.

  • Due-date ring card: "₹9,500 due in 5 days" as a countdown ring, UPI QR (already built) one tap away, deep-links to GPay/PhonePe/Paytm intents
  • Simple passbook timeline — every entry with a receipt download; HRA receipt bundle for tax season as a one-tap ZIP/PDF
  • Maintenance ticket tracker with photo upload and status stepper (you have the schema hooks)

◈ Reports & Ledger

"Intentionally simple" today — three charts turn it into the owner's favorite page.

  • YoY collection bars per property, occupancy trend line, and per-property P&L (rent collected − expenses) — all from existing tables
  • Branded Recharts theme: teal/gold gradients, warm gridlines, dark-mode synced (replaces the current indigo/slate palette drift)
  • Keep CSV export; add "Email me this monthly" via your Edge Function pattern

07 · Visibility & Growth

Modern is also findable.

You asked for "more visible" — that's an engineering track as much as a design one. Ranked by impact per hour invested.

01
Ditch HashRouterCrawlable URLs (/dashboard, not /#/dashboard). On GitHub Pages use the 404.html SPA trick, or — better — host on Cloudflare Pages/Vercel with SPA rewrites and a real domain. Highest-visibility fix there is.
02
Per-route titles + metaA 15-line useDocumentTitle() hook: "Tenants · RentBook", "Bills · RentBook". Search engines and browser tabs both benefit.
03
Social cards + landing pageOG/Twitter image with the Warm Ledger palette; a public marketing page at / (screenshots, UPI + PDF receipt story) linking to /login. Right now the root is a redirect — zero shareable surface.
04
Performance budgetRoute-level React.lazy code-splitting (jsPDF alone is heavy), preconnect to your Supabase host, compress property cover images to WebP. Target Lighthouse 90+ mobile — elderly users on mid-range Androids are your core audience.
05
PWA install prompt, surfacedThe manifest + service worker exist — add an in-app install banner ("Install RentBook → your bills stay put even on flaky data") and iOS A2HS coaching. Retention multiplier for daily-use owners.
06
Unified ⌘K omnisearchMerge per-page searches into one command palette (tenants, rooms, bills, receipts, actions like "Generate bills"). Also erases your "per-page search" known limitation — one stone, two birds.
